三種語言的分工

語言負責展覽網站的例子
HTML內容與結構這是標題、這是引文
CSS外觀與排版行距、顏色、手機版寬度
JavaScript互動切換夜間閱讀

常用 HTML

標籤用途
<h1>～<h6>標題；每頁通常一個 h1
<p>段落
<br>詩句或引文內換行
<blockquote>引文區塊
<a href="網址">超連結
<img src="路徑" alt="圖片說明">圖片；alt 是讀不到圖片時的替代文字
<header> <main> <article> <footer>頁首、主要內容、獨立文章、頁尾

常用 CSS

選擇器 {
  屬性: 值;
}

line-height  行距      font-size   字體大小
color        文字色    background  背景
max-width    最大寬度  margin      外距
padding      內距      border      邊框

F12 檢查

  • Elements／Styles：看結構和樣式；在這裡的修改不會存回檔案。
  • Console：紅字代表錯誤，例如檔案找不到（404）。
  • Ctrl+Shift+M：切換手機模式。

對 AI 下指令的範本

檔案：works/s01/style.css
目標：把 blockquote 的上下留白改成 32px
限制：只能改這個檔案，不要改文字內容，不要新增外部資源
回報：列出你改了哪些規則

AI 工具類型

建議課堂上統一用網頁聊天型，已經習慣用編輯器型的人也可以繼續用，但要遵守下表的限制。

網頁聊天型（ChatGPT、Claude、Gemini 網頁版）編輯器型（Copilot、Cursor、Claude Code）
運作方式自己貼上程式碼，再把結果貼回檔案AI 直接修改專案檔案
課堂優點通常有免費方案，操作也比較一致；每次都會看到要貼回的內容速度快，也最接近多數人平常 vibe coding 的方式
課堂風險免費額度可能用完；可能貼錯位置可能一次改到很多檔案，甚至動到別人的資料夾
課堂規定只貼需要修改的段落，或自己的單一檔案指令中要限定「只能改我的資料夾」

Git 用語與救急

用語意思GitHub Desktop
Commit在自己電腦存一個版本Commit to 分支名稱
Push把版本送上 GitHubPush origin／Publish branch
Pull把 GitHub 的新版本拿回來Fetch origin → Pull origin
Branch自己的工作空間Current Branch → New Branch
Pull Request請別人檢查後合併Create Pull Request
  • 還沒 commit 想放棄：Changes 對檔案按右鍵 → Discard Changes。
  • 已經 commit 想復原：History 對版本按右鍵 → Revert Changes in Commit。
  • 看到衝突（conflict）：先不要亂改，截圖找負責的同學。

送出前檢查

  • 只改到自己的資料夾。
  • 作品文字沒有被改動或刪除。
  • 電腦版和手機版都看過。
