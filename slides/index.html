潮間帶虛構展｜教學練習

看懂網頁，才能好好跟 AI 一起做

網頁結構、GitHub 與協作入門

今天結束時，你要能做到四件事

看得懂

知道 AI 改了哪裡、大致改了什麼。

說得準

能指出元素與屬性，不只說「那邊怪怪的」。

驗得出

會用 F12 和手機模式檢查問題。

救得回

會查看並還原版本，不覆蓋別人的檔案。

今天的流程

  1. 網站如何運作
  2. HTML：幫作品標出結構，第 1 輪找碴
  3. CSS 和 F12：調整閱讀體驗，第 2 輪找碴
  4. GitHub：存版本、看歷史、還原
  5. AI 協作：下指令、檢查變更，第 3 輪找碴
  6. Pull Request 上線，概念大補帖

打開網站時，發生了什麼？

  1. 瀏覽器依照網址，向伺服器要檔案。
  2. 伺服器回傳 HTML、CSS、JavaScript 和圖片。
  3. 瀏覽器讀懂檔案，把它們畫成你看到的畫面。

網站就是放在網路上的一包檔案。GitHub Pages 負責把它們放到網路上。

三種語言，各做各的事

HTML

內容與結構
這是標題、這是引文

CSS

外觀與排版
行距、顏色、手機版

JavaScript

互動
按鈕切換夜間閱讀

作品內容應該放在 HTML；想改外觀就去 CSS，不需要動到文字。

這個資料夾，就是一個網站

exhibit-practice/
├─ index.html        首頁
├─ css/site.css      共用外觀
├─ js/site.js        夜間閱讀按鈕
└─ works/
   ├─ s01/
   │  ├─ index.html  你的作品內容
   │  ├─ style.css   你的作品外觀
   │  └─ images/     你的作品圖片
   └─ s02/ ...       別人的資料夾，不要動

任務 0

先把檔案拿到自己的電腦

  1. 打開任務卡。
  2. 用 GitHub Desktop 依序選 File → Clone repository → URL。
  3. 用 VS Code 打開資料夾，找到自己的 works/s編號/。

Clone 的意思是：把 GitHub 上的專案複製到自己的電腦。20:30 已做完的人，確認看得到 works 資料夾即可。

HTML

標籤就是告訴瀏覽器：這是什麼

<h1>退潮時分的郵筒</h1>
│ │        │       └ 結束標籤
│ │        └ 內容
│ └ 標籤名稱：一級標題
└ 起始標籤

標籤之間可以層層包住；先打開的，後關閉。

HTML

屬性提供額外資訊

<a href="https://example.com">作者介紹</a>
<img src="images/cover.svg" alt="潮間帶抽象插圖">
  • href：連結要前往哪裡。
  • src：圖片檔案在哪裡；這是相對路徑，從目前檔案的位置開始找。
  • alt：圖片讀不到時的替代文字。

HTML

每個網頁的基本骨架

<!doctype html>
<html lang="zh-Hant">
  <head>  給瀏覽器看的資訊：標題、編碼、CSS </head>
  <body>  給讀者看的內容 </body>
</html>

結構標籤讓文件更有條理：header、main、article、footer。

HTML × 文學作品

瀏覽器會把換行和連續空白壓成一個空白

散文、小說

每段用 <p>。

詩、引文

分行要明確用 <br>；直排可用 CSS 的 writing-mode: vertical-rl。

展覽原則

排版可以改，作者的文字不能被悄悄改動。

任務 1｜12 分鐘

幫作品標上 HTML 結構

  • 打開 works/s編號/index.html。
  • 只加標籤，不改文字。
  • 做完到任務卡檢查，並勾選進度表。

卡關順序：任務卡 2 分鐘 → 勾「需要協助」並貼截圖 → 進度檔。

第 1 輪找碴｜5 分鐘

這一頁有什麼問題？

  1. 打開找碴頁，也可以用 F12。
  2. 把答案填進表單：位置、問題、要怎麼跟 AI 說。
  3. 時間到再一起公布；不計分。

CSS

CSS 只有一個基本句型

blockquote {          /* 選擇器：要改誰 */
  line-height: 1.9;   /* 屬性: 值; */
  color: #17313b;
}

選到誰，就改誰。選擇器拼錯時，規則不會生效，也不一定會報錯。

CSS

盒模型：每個元素都是一個盒子

padding

內距：內容到邊框的距離

border

邊框

margin

外距：與其他元素的距離

長文閱讀最常調的是：font-size、line-height、max-width。

F12

瀏覽器內建的檢查工具

  • Elements／Styles：點選元素，看它套了哪些規則；可試改，但不會存回檔案。
  • Console：紅字代表錯誤；看到 404 通常是路徑錯了。
  • Ctrl+Shift+M：切換手機模式。

JavaScript 今天只要知道：它負責互動，出錯時先看 Console。

任務 2｜7 分鐘

用 F12 試，再寫回 CSS

  • 調整內文寬度、字體大小和行距。
  • 開手機模式，確認圖片沒有超出畫面。
  • 把數值寫進 style.css，存檔後按 F5。

打開任務 2

第 2 輪找碴｜3 分鐘＋公布答案

同時檢查電腦版和手機版

打開找碴頁，用 F12 確認問題。

表單還是填三件事：位置、問題、要怎麼跟 AI 說。

休息 5 分鐘

回來前，請先打開 GitHub Desktop。

GitHub

Git 像存檔，GitHub 像雲端和協作平台

Git

記錄檔案每個版本的工具。

GitHub

放專案、一起協作和檢查的網站。

GitHub Desktop

不用打指令，用按鈕操作 Git。

GitHub

今天只要記住這條路

修改檔案 → Commit 存版本 → Push 上傳 → Pull Request 請求合併
                                           ↓
別人的新版本 ← Pull 拿回來 ← main 正式版本 ← 講師檢查並合併

每個人都在自己的分支工作，這樣不會直接動到正式版本，也比較不會互相擋住。

任務 3｜跟著操作

開分支、存版本、看歷史

  1. 建立分支：名稱用自己的編號。
  2. 查看 Changes：只該改到自己的資料夾。
  3. Commit，再 Publish branch。
  4. 到 History 看剛才的版本。

接著看講師示範：刪掉一段文字後，怎麼用 Revert 救回來。這一步不用跟著做。打開任務 3

AI 協作

今天用哪種 AI？

建議課堂上統一用網頁聊天型，已經習慣用編輯器型的人也可以繼續用，但要遵守下表的限制。

網頁聊天型（ChatGPT、Claude、Gemini 網頁版）編輯器型（Copilot、Cursor、Claude Code）
運作方式自己貼上程式碼，再把結果貼回檔案AI 直接修改專案檔案
課堂優點通常有免費方案，操作也比較一致；每次都會看到要貼回的內容速度快，也最接近多數人平常 vibe coding 的方式
課堂風險免費額度可能用完；可能貼錯位置可能一次改到很多檔案，甚至動到別人的資料夾
課堂規定只貼需要修改的段落，或自己的單一檔案指令中要限定「只能改我的資料夾」

AI 協作

好的指令，要讓 AI 知道範圍

檔案：works/s01/style.css
目標：把 blockquote 的上下留白改成 32px
限制：只能改這個檔案，不要改文字內容，不要新增外部資源
回報：列出你改了哪些規則

不管用哪一種工具，都要用 GitHub Desktop 檢查實際改了哪些檔案和哪幾行。

任務 4｜6 分鐘

請 AI 修改，再檢查

  • 請 AI 調整 blockquote 的樣式。
  • 確認畫面正確，文字也沒有變。
  • 看 Changes，檢查無誤再 Commit、Push。

打開任務 4

第 3 輪找碴｜3 分鐘＋公布答案

AI 真的只改了要求的地方嗎？

打開模擬變更記錄，找出不該發生的變更。

文學作品最怕的不是版面錯，而是文字被悄悄改掉，卻沒有人發現。

任務 5｜跟著操作

發 Pull Request，上線

  1. 按 Create Pull Request，確認 base 是 main。
  2. 自我檢查：只改自己的資料夾、文字沒有變動、寫一句說明。
  3. 把連結貼到聊天室，由講師合併。

講師會依進度決定：大家一起發，或先看示範、課後再協助發。網站更新可能要等 1 到 10 分鐘。打開任務 5

概念大補帖

網頁：一次帶回去

HTML

標內容的結構。標籤、屬性、相對路徑。

CSS

選到元素後改外觀。選擇器、盒模型、行距和寬度。

JavaScript

負責互動。出錯時先看 Console。

F12

看結構、試樣式、查錯誤、檢查手機版。

概念大補帖

協作：一次帶回去

Commit／Push

存版本，再上傳到 GitHub。

Branch／PR

在自己的分支工作，檢查後才合併。

Revert

版本有誤時，從歷史還原。

AI 指令

說清楚檔案、目標、限制、回報。

正式專案也照這樣做

  1. 每人只改自己負責的資料夾。
  2. 下指令前先指定檔案和範圍。
  3. 交出前看 Changes、電腦版和手機版。
  4. 確認作者的文字一字未改。
  5. 用 Pull Request 交給負責人合併。

課後可以再做一次找碴頁，並留著速查表。請用聊天室的連結填寫匿名回饋表單。
